# False-Positive Study Artifact

This directory contains the inputs and scripts required to reproduce the
balanced OCA-vs-Daikon invariant sample used in the false-positive manual
evaluation.

## Overview

The study compares invariants produced by OCA and Daikon on the same sampled
methods.

The reproduction consists of three deterministic stages:

1. matched-method sampling;
2. balanced invariant sampling;
3. representation filtering and deterministic replacement/downsampling.

The final dataset contains:

- 179 OCA invariants;
- 179 Daikon invariants;
- 358 invariants total;
- 60 originally sampled matched methods;
- 57 methods contributing at least one invariant after representation
  filtering.

## Requirements

The scripts require:

- Python 3
- standard Python library only
- Bash for `run_reproduction.sh` and `verify_artifact.sh`

No network access is required.

## Stage 1: Matched-Method Sampling

Run:

    python sample_oca_daikon_matched.py

Random seed:

    42

For each project, the script samples OCA methods and retains a method only if
the corresponding method is present in the Daikon output. Sampling continues
until 10 matched methods have been selected for each project.

There are six projects, producing 60 matched methods in total.

OCA invariants used for method eligibility are observed-held invariants. Their
metadata is recovered from the included OCA registry/outcome data.

## Stage 2: Balanced Invariant Sampling

Run:

    python balance_sampled_invariants.py

Random seed:

    43

For each of the 60 selected matched methods, let:

    k = min(number of OCA observed-held invariants,
            number of Daikon invariants)

The script samples exactly `k` OCA invariants and `k` Daikon invariants for
that method.

This produces the initial balanced sample before representation filtering.

## Stage 3: Representation Filtering and Final Balancing

Run:

    python reproduce_final_from_manual_verdicts.py

Representation annotations are provided in:

    manual-daikon-verdicts.tsv

Each Daikon candidate has a representation status and, when applicable, its
common Java-like expression.

The representation file is an external annotation input to this reproduction
pipeline. It should be treated as a curated annotation file rather than as an
output generated by the reproduction scripts.

For each sampled method, the final number of invariants per system is:

    final_k =
        min(initial_k,
            number of accepted Daikon representation candidates)

Accepted originally sampled Daikon invariants are preserved whenever
possible.

If a sampled Daikon invariant is unavailable after representation filtering,
a replacement is deterministically sampled from the remaining accepted
Daikon invariants for the same method.

Random seed for replacement/downsampling:

    44

If the final Daikon count for a method is smaller than the initial balanced
count, the OCA sample is downsampled to the same `final_k`, maintaining equal
numbers of OCA and Daikon invariants for each contributing method.

The reviewer-facing rows are shuffled using:

    seed 45

## One-Command Reproduction

Run:

    ./run_reproduction.sh

This removes previously generated study outputs and executes all three stages
from the included raw inputs.

Expected final output:

    Final OCA: 179
    Final Daikon: 179
    Final total: 358
    Daikon replacements: 81

and:

    Methods: 60
    Methods contributing >=1 invariant: 57
    OCA: 179
    Daikon: 179
    Total: 358

## Generated Final Files

The final study outputs are written under:

    artifact_reproduction/

The main files are:

    final-balanced.jsonl
    final-balanced-audit.tsv
    final-method-summary.tsv
    reviewer-dataset.tsv
    reviewer-answer-key.tsv

`final-balanced-audit.tsv` is the internal complete dataset.

`reviewer-dataset.tsv` contains the shuffled reviewer-facing expressions.

`reviewer-answer-key.tsv` contains the corresponding source-system labels and
should not be provided to reviewers during blinded evaluation.

## Verification

Run:

    ./verify_artifact.sh

The verification script checks:

1. all required input files exist;
2. the reproduction scripts contain no absolute path to the original
   `/project/mjk76/ea442/promptstudy` directory;
3. all Python reproduction scripts compile;
4. the full reproduction pipeline succeeds;
5. exactly 60 matched methods are reproduced;
6. exactly 179 OCA and 179 Daikon final invariants are produced;
7. the reproduced invariant multiset is identical to the stored reference;
8. all final Java-like expressions are identical to the stored reference.

A successful verification ends with:

    PERFECT REPRODUCTION

## Random Seeds

The fixed seeds used by the study are:

    42  matched-method sampling
    43  balanced invariant sampling
    44  representation replacement/downsampling
    45  reviewer-row shuffling

## Reference Outputs

Files under `reference_outputs/` are not inputs to the reproduction pipeline.

They are retained only so that `verify_artifact.sh` can confirm that a fresh
execution reconstructs the originally selected methods and final invariant
dataset exactly.

## Portability

The reproduction scripts resolve paths relative to this directory rather than
using paths from the original experimental environment. Therefore the entire
directory may be copied to another location and executed from there.
